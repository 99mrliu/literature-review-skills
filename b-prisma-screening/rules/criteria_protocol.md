# 纳入/排除标准协议（criteria_protocol）

## 顺序（不可颠倒）

1. 从 case.json / task.md 提取研究问题原句，抄写到 criteria.md 顶部。
2. 把研究问题分解为 2–4 个**可判定方面**：研究对象/人群、干预或方法、结局或指标、场景或条件。每个方面至少支撑一条纳入标准。
3. 写纳入标准 IC1…ICn：每条一句话，形如"报告了 X 在 Y 条件下的 Z 指标"。措辞必须来自研究问题，不得引入问题之外的偏好。
4. 写排除标准 EC1…ECm：覆盖——非原始研究（综述、社论、评论）；对象不符；未报告相关结局；会议摘要且无可用数据；重复发表；全文不可用且摘要信息不足以满足任一 IC。
5. **保存 criteria.md 之后**才允许阅读结论、做主题归纳。标准一旦写入，本轮运行不得回改；若发现标准有缺陷，记入 change_log 并在 uncertainties 说明，而不是静默修改。

## 判定纪律

- 每条筛选决定必须引用标准编号（`criteria_ids`），理由（`reason`）必须说清该篇满足/不满足/触发的是哪一条、依据是题录信息还是全文内容。
- 拿不准的篇目默认 `exclude`，理由写"信息不足以判定 IC#"；不得因为标题不吸引人而排除。
- 排除理由按标准编号聚合后进入 PRISMA 排除理由分布（prisma_flow.md），因此理由措辞要能与编号对应。
- 会议版与期刊版、预印本与正式版视为同一研究：保留信息全者（通常期刊版），其余 `duplicate_of`。
